Sprint brief: promo codes at checkout and a live cart total

Two small storefront features for this sprint. Both touch the checkout total, so ownership must be clear.

1 · Background

Customers ask for promo codes at checkout, and the header shows only an item count. Shoppers can't see what they'll pay until the last step.

2 · Scope

IDFeatureAcceptance criteriaArea
F1Promo code at checkout
  • A valid code applies its discount
  • An invalid code shows an inline error
  • The order total recalculates at once
checkout, promo
F2Live cart total in header
  • Badge updates on add and remove
  • Shows the discounted total
  • Formatted in IDR
header, cart badge

3 · Constraints

The header total must read from checkout's calculateTotal(). One source of truth for the price.

4 · Out of scope

  • Payment provider changes
  • Admin UI for creating codes
