[p] How it works
[h2] How three Bobs share one repo
[code] lock_guard
[h3] One file, one Bob
[p] A PreToolUse hook checks the shared lock table before any write. Andi holds checkout.ts, so no other Bob can overwrite it.
[code] radar.why_blocked
[h3] A near-miss explains itself
[p] The blocked Bob calls an MCP tool and tells its human, in one sentence, who holds the file and what to do next.
[code] pm-lead
[h3] PM Bob proposes, a human decides
[p] The pm-lead mode can only read and propose. Plans and conflicts land in Needs you, where a person clicks Approve or Deny.
[code] radar-mcp
[h3] Every teammate keeps their own Bob
[p] Each person runs IBM Bob on their own machine. Live Collab syncs locks, tasks and hook traces between them in real time.
[h3] Visible
[p] Every Bob shows its owner, file and last hook on one screen.
[h3] Locked
[p] A file has one holder. Others queue or switch files, never merge by accident.
[h3] Human-approved
[p] Agents suggest. A person approves the plan before work starts.
[p] Near-miss
[h2] Catch the near-miss before it merges.
[p] Two Bobs reach for the same file. The hook stops the second one, the Bob says why, and its human keeps working on something else.
[p] Blocked, then queued
[p] lock_guard stops the write before it lands. Budi's Bob waits at position 1 and moves on to Header.tsx.
